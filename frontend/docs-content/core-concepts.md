# Core Concepts and Terminology

To fully leverage the power of API Guardian, it is essential to understand the core terminology and conceptual models that underpin the platform. 

## 1. Provider
A **Provider** represents the third-party service that owns and maintains an API. Examples include Stripe, Twilio, GitHub, or OpenAI. Providers are the entities that issue notices and update OpenAPI specifications.

## 2. Guarded API
A **Guarded API** is a specific dependency that you have explicitly instructed API Guardian to monitor. You are not just monitoring the provider as a whole; you are monitoring specific versions and services. When you add a Guarded API, you establish the defensive perimeter.

## 3. Provider Notice
A **Provider Notice** is any communication from a Provider indicating a change to their API. This could be a breaking change, a deprecation, a sunsetting timeline, or a security requirement. Our intelligence engine parses these notices and extracts structured metadata.

## 4. Maintenance Case
When a Provider Notice is deemed relevant to your codebase (meaning it affects a Guarded API you actually use), API Guardian opens a **Maintenance Case**. A case is the central entity tracking the end-to-end lifecycle of resolving the upstream change. It tracks the status of AST parsing, patch generation, verification, and PR merging.

## 5. Blast Radius
The **Blast Radius** is a calculated metric indicating the scope of impact a Provider Notice has on your organization. It represents the number of repositories, files, and specific functions that will need to be updated to comply with the upstream change.

## 6. Migration Patch
A **Migration Patch** is the actual code generated by our highly-specialized LLMs. It is a syntactically correct `git diff` that modifies your codebase to use the new API specifications while preserving all surrounding business logic.

## 7. Verification Sandbox
The **Verification Sandbox** is the ephemeral, zero-network AWS Fargate container where your code is tested against the generated patch. It provides cryptographic proof that the migration will not break your application at runtime.

Mastering these concepts will allow you to navigate the dashboard with ease and clearly communicate the value of autonomous maintenance to your team.
